# M1 – OIDC sign-in: design

Status: draft · Date: 2026-10-09 · Branch: `feat/m1-oidc-sign-in`

Replaces the multi-tenant SSO design of closed PR #179. The maintainer decided:
one OIDC connector, no multi-tenancy (no organizations, no `tenant_id`/RLS), no
roles, for now. Keep it to standard Better Auth features.

## Goal

Users sign in through one OIDC identity provider (IdP) and sign out. The rest
of the app can require a signed-in user.

**Done when:** `task ci` passes locally and in GitHub Actions, the tests below
exist and pass, the PR has been reviewed by a reviewer subagent and the
maintainer has approved the merge.

## Non-goals

- Multi-tenancy (organizations, `tenant_id`, RLS), roles, invitations. This
  overrides the brief's rule 1 for now; adding tenancy later means adding
  `tenant_id` and RLS to every domain table (accepted).
- Several IdPs, SAML, email/password (also not in development), email.
- Access control beyond the IdP: everyone the IdP authenticates may sign in;
  operators restrict access by assigning the app in their IdP.
- Rate limiting (switched off explicitly; Better Auth would otherwise enable an
  in-memory limiter in production).

## Decisions

| Topic | Decision |
|---|---|
| Libraries | `better-auth` 1.7.7 (exact), Drizzle adapter, the built-in `genericOAuth` plugin. No SSO plugin, no organization plugin. |
| Connector | One `genericOAuth` provider, id `oidc`, from env: `OIDC_DISCOVERY_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` (all required, Zod-validated in `getEnv()`). `pkce: true`, `scopes: ["openid", "email", "profile"]`, `requireIdTokenVerification: true` (the ID token is verified against the IdP's JWKS from discovery). The secret lives only in env. |
| Discovery | Done by the plugin when the auth instance is created (first request). If discovery fails, Better Auth skips the provider and logs it; `getAuth()` then does not keep that instance, so the next request retries (an IdP outage at start-up heals by itself). |
| Endpoints | Better Auth's standard ones: `POST /api/auth/sign-in/social` (`provider: "oidc"`), `GET /api/auth/callback/oidc`, `get-session`, `sign-out`. No custom allowlist: email/password is not enabled, so its endpoints reject on their own. |
| Sessions | Database sessions, cookie cache off, secure cookies when `BETTER_AUTH_URL` is https. Absolute lifetime `12 * 60 * 60` seconds without refresh, so a user removed at the IdP loses access within 12 hours. |
| Tables | Better Auth's `user`, `session`, `account`, `verification` in schema `auth` (owned by `agenty_owner`, `agenty_app` gets privileges via grants and default privileges, as for `app`). `src/server/db/auth-schema.ts` is generated by `task auth:generate` (Better Auth CLI) from the schema-relevant options shared with `createAuth`, never edited by hand. uuid ids. |
| Stored tokens | `account.encryptOAuthTokens: true`. |
| Configuration | New env: `BETTER_AUTH_SECRET` (≥ 32 chars), `BETTER_AUTH_URL`, the three `OIDC_*`. `.env.example` points at the mock IdP. The auth instance is created lazily (`getAuth()`), so `next build` needs no runtime env. |
| Server API | `src/server/auth/session.ts`: `getCurrentUser()` → `{ id, name, email } \| null` (React `cache`, one lookup per request) and `requireUser()` (redirects to `/sign-in`). Later milestones use these. |
| UI | Root layout: header (app name, user menu with name, email, sign out) for signed-in users, and the shared `<main>`. `/sign-in`: one "Sign in" button (`authClient.signIn.social({ provider: "oidc", callbackURL: "/", errorCallbackURL: "/sign-in" })`), fixed error messages for `?error=` (never IdP text). `/`: signed out → landing with sign-in link; signed in → placeholder ("Agents arrive in the next milestone"). No `proxy.ts` (no protected pages yet; `requireUser()` covers future ones). |
| Dev/CI IdP | `ghcr.io/navikt/mock-oauth2-server:6.0.5` in docker-compose and the CI `ci` job, issuer `http://localhost:8080/agenty` (always `localhost`). Its login form takes any username and claims JSON. |

## Tests

- Unit: env validation (new variables, secret not echoed).
- Integration (dev database + mock IdP, through a helper that drives the real
  flow over HTTP): first sign-in creates user, account and session; a second
  sign-in reuses the user; the account's access token is not stored in plain
  text; a failing discovery leaves no cached instance (next `getAuth()`
  retries); `getCurrentUser()` with and without a session.
- Roles test widened to schema `auth` (ownership, grants, no CREATE for the app
  role).
- E2E: landing when signed out; sign in through the mock IdP → placeholder and
  header with the user's name; sign out → landing; an IdP error redirect shows a
  fixed message.
